# 아키텍처

## 구성

```text
GitHub Pages (공개 정적 파일)
  ├─ Firebase Authentication: Google 로그인
  ├─ App Check: 비정상 클라이언트 요청 완화
  ├─ Gmail API: 관리자가 승인한 계정으로 PDF 첨부 발송
  └─ Cloud Firestore
       ├─ 관리자: 인사·수업·조건·급여 전체 관리
       └─ 선생님: 본인의 published 명세서만 조회
```

GitHub에는 HTML, CSS, JavaScript, 보안 규칙과 가상 데이터만 둡니다. 급여 원본과 결과는 브라우저가 Firebase Web SDK로 Firestore에 직접 저장하며, 모든 요청은 Authentication UID와 Security Rules로 다시 검사합니다.

## 월 급여 흐름

1. 선생님과 과목별 시급·계약 조건을 적용 기간과 함께 등록합니다.
2. 수업 내역을 직접 입력하거나 CSV로 올립니다.
3. 각 수업에 당시 시급, 소득 구분, 보험 적용 여부를 복사해 스냅샷을 만듭니다.
4. 선생님별 수업을 `employee`, `business`, `other`, `exempt` 버킷으로 분리 계산합니다.
5. 자동 공제와 회계사가 확인한 수동 공제를 함께 검토합니다.
6. 급여 확정 시 선생님별 명세서, 월 마감, 감사 로그를 Firestore batch로 한 번에 저장합니다.
7. 관리자는 포털 로그인 안내문을 보내거나, 확정본을 검토한 뒤 관리자 Gmail 계정으로 PDF를 첨부 발송합니다.
8. 확정 문서는 수정·삭제하지 않습니다. 선생님은 자신의 UID가 적힌 `published` 문서만 조회합니다.
9. 선생님의 최초 열람 시 원본과 분리된 `payslipReceipts` 문서를 생성합니다. 재열람은 최초 시간을 덮어쓰지 않습니다.
10. Gmail 발송 성공 시 원본과 분리된 `payslipDeliveries` 문서에 수신자·시각·메시지 ID만 기록합니다. OAuth 토큰과 PDF는 저장하지 않습니다.
11. 관리자는 월 급여내역서를 CSV 또는 PDF로 내려받아 회계사와 합의한 안전한 채널로 직접 전달합니다. 회계사는 앱이나 Firebase에 로그인하지 않습니다.

## 혼합 계약 처리

소득 구분은 선생님 문서 하나에 고정하지 않고 수업 내역마다 둡니다. 예를 들어 같은 선생님의 `고등 수학`은 근로소득/보험 적용, `논술 특강`은 사업소득/보험 미적용으로 저장할 수 있습니다. 계산기는 두 금액과 공제를 별도로 계산한 뒤 하나의 월 명세서로 합산합니다.

세금과 사회보험 정책도 분리합니다. `taxPolicies`는 국세청 원천징수 기준과 근로소득 간이세액표를, `insurancePolicies`는 관련 공단의 사회보험 기준을 시행일별 버전으로 보관합니다. 월 계산 시 유효한 최신 버전을 선택하고 확정본에는 두 버전과 계산 결과를 함께 스냅샷으로 저장합니다.

시급 규칙은 `teacherId + subjectId + classId + effectiveFrom/effectiveTo`로 찾습니다. 더 구체적인 규칙을 우선하며, 실제 수업 내역에는 적용 결과를 복사합니다. 따라서 다음 달 시급을 변경해도 지난달 확정본은 변하지 않습니다.

## Spark와 Blaze 경계

Spark MVP에서는 관리자 브라우저가 계산과 Firestore 저장을 수행합니다. 계산 결과를 믿기 전에 Security Rules와 확정 전 검토가 필수입니다.

Blaze 단계에서는 다음을 Cloud Functions로 옮기는 것이 좋습니다.

- 서버 기준 급여 재계산 및 변조 검증
- PDF 원본의 서버 생성과 장기 보관
- 예약·일괄 이메일 자동 발송
- 실패 재시도와 발송 이력
- 취소·재발행 워크플로
- Secret Manager의 메일 API 키 관리
