# QA 절차

모든 기능·설정·문서 변경은 커밋 전에 아래 명령을 실행하고 통과해야 합니다.

```bash
npm run qa
```

## 자동 검사 범위

- 근로소득 월급, 단일/복수 사업소득 시급 × 수업 시수, 수업 없는 가입자, 혼합 지급과 공제 보정 단위 테스트
- 보험별 가입 기간·서로 다른 신고 기준액, 국민연금 천원 미만 절사, 자동 보험료 10원 미만 절사와 건강+요양 합산 수동값 단위 테스트
- 선생님 등록·수정 화면에서 적용 기간 옆 보험별 예상 보험료와 그 아래 소득세·지방소득세가 가족 수·자녀 수·원천징수 비율에 따라 갱신되는지 확인
- 교통비·주차료·기타 지급의 과세 처리, 미확인 항목 확정 차단과 회계사용 집계 테스트
- 국세청 간이세액표 공식 예시, 80/100/120% 선택, 고액 급여 산식 테스트
- 사업소득 3.3%, 기타소득 필요경비·과세최저한·지급 건 그룹 테스트
- 세금 정책 시행일 선택과 간이세액표 CSV 검증 테스트
- 모든 JavaScript와 MJS 파일 문법 검사
- 필수 정적 파일과 화면 영역 존재 확인
- `index.html`의 로컬 CSS·JavaScript 참조 확인
- 로컬 서버의 HTML, CSS, 앱 JavaScript HTTP 응답 확인
- 개인키·클라이언트 비밀키·비밀번호 패턴 검사
- 데모 이메일의 `.invalid` 도메인 확인
- 전체 주민등록번호 필드의 Firestore 저장 차단과 생년월일 자리별 입력·뒷자리 마스킹·검증 확인
- 관리자·선생님 휴대전화 입력에서 `010`이 고정되고 뒤의 숫자 8자리만 입력되는지, Firestore 저장값에는 하이픈이 없는지 확인
- 이름에 한글·영문과 단어 사이 공백만 입력되는지, Tab 순서와 휴대전화·생년월일 완성 시 다음 칸 자동 이동 확인
- 급여명세서 파일명 정규화와 Gmail MIME PDF 첨부 인코딩 테스트
- 교사 PDF 다운로드, 관리자 확정본 발송 모달, 미확정본 발송 차단 확인
- 접근 요청 이메일 일치 검증, 미등록 선생님 자동 생성·계정 연결, 이메일 재입력 삭제 확인, 수업시간·미확정 기록 동시 정리와 확정 급여·명세서 기록 보유 선생님 삭제 차단 확인
- 선생님 자기정보의 보험 가입·한 개/여러 개 시급 허용과 이메일·월급·보험 신고 기준 변경 차단 규칙 확인
- 본인 월별 수업시간 저장, 관리자 시급 결합과 확정 월 잠금 확인
- 선생님 수업시간 저장과 관리자 알림 batch 생성, 본인 알림만 쓰기·관리자만 읽기 규칙 확인
- 관리자 알림 읽음 처리와 해당 선생님·급여월의 월 지급액 입력 바로가기 확인
- 급여 확정 취소, 불변 버전 보관, 재발행 차수와 현재 차수 이력 선택 테스트
- 발송 성공 이력의 관리자 전용 조회 및 불변 규칙 확인
- 사용 설명서 검색 관련도와 AI 도움말 개인정보 형태 감지 테스트
- Gemini 프롬프트가 관련 설명서와 현재 메뉴만 포함하는지 확인
- AI 도움말 화면, Firebase AI Logic 프록시와 공개 설정의 비밀키 미포함 확인
- GitHub Actions 워크플로가 없는지 확인

## AI 도움말 수동 검사

1. 관리자 메뉴 맨 아래에 `사용 설명서`가 표시되는지 확인합니다.
2. 설명서에서 `명세서 이메일`을 검색해 개인 명세서 안내가 나오는지 확인합니다.
3. 모든 관리자 탭 왼쪽 아래에서 `AI 도움말` 패널이 열리는지 확인합니다.
4. 테스트 이메일과 휴대전화 번호를 포함한 질문이 외부 AI 호출 없이 차단되는지 확인합니다.
5. 선생님 계정에는 관리자 설명서와 AI 도움말 버튼이 표시되지 않고, 관리자 전용 화면으로 전환되지 않는지 확인합니다.
6. App Check 지표에서 관리자와 선생님의 `payroll.robertson.kr` 요청이 reCAPTCHA Enterprise의 유효 요청으로 집계되는지 확인합니다.
7. 선생님 계정에서 `등록 정보`의 개인정보·보험 가입 여부·한 개/여러 개 시급을 수정하고 재로그인 후 유지되는지 확인합니다. 여러 시급은 `시급 1`, `시급 2`로 자동 표시되고 과목명 입력란이 없어야 합니다.
8. `수업시간 입력`에서 근로소득·사업소득 수업시간을 저장한 뒤 관리자 `월 급여 입력` 계산에 반영되는지 확인합니다.
9. 관리자 계정으로 다시 로그인해 상단 종 아이콘에 미확인 개수가 표시되는지 확인합니다.
10. 알림을 눌렀을 때 제출한 선생님과 급여월의 월 지급액 입력 창이 열리고 알림이 읽음 처리되는지 확인합니다.
11. 급여 확정 후 같은 월의 수업시간 저장 버튼이 비활성화되고 Firestore 쓰기도 거부되는지 확인합니다.
12. Gemini 장애 또는 미설정 상태에서 내장 설명서 답변이 표시되는지 확인합니다.
13. 데스크톱과 모바일에서 패널, 입력창과 닫기 버튼이 겹치지 않는지 확인합니다.

## Git 커밋 전 자동 실행

최초 복제 후 한 번 아래 설정을 적용하면 저장소의 pre-commit 훅이 `npm run qa`를 자동 실행합니다.

```bash
git config core.hooksPath .githooks
```

QA가 실패하면 커밋하지 않고 원인을 수정한 뒤 전체 QA를 다시 실행합니다. Firebase 실제 연결 후에는 관리자, 선생님, 미등록 계정으로 Security Rules 허용·거부 테스트도 추가해야 합니다.
