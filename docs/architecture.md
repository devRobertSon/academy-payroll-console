# 아키텍처

## 구성

```text
GitHub Pages (공개 정적 파일)
  ├─ Firebase Authentication: Google 로그인
  ├─ App Check: 비정상 클라이언트 요청 완화
  ├─ Gmail API: 관리자가 승인한 계정으로 PDF 첨부 발송
  └─ Cloud Firestore
       ├─ 관리자: 계정 승인·근로소득 월급·보험 신고 기준·세금·월 마감 관리
       └─ 선생님: 기본 정보·보험 가입 여부·시급·월별 수업시간 입력, 본인의 published 명세서 조회
```

GitHub에는 HTML, CSS, JavaScript, 보안 규칙과 가상 데이터만 둡니다. 급여 원본과 결과는 브라우저가 Firebase Web SDK로 Firestore에 직접 저장하며, 모든 요청은 Authentication UID와 Security Rules로 다시 검사합니다.

## 월 급여 흐름

1. 미등록 Google 승인 요청은 관리자가 신규 선생님 문서와 사용자 연결을 한 batch로 만들고, 선생님이 로그인 후 개인정보·보험 가입 여부·시급을 완성합니다.
2. 관리자는 보험 신고 기준액·적용 기간, 기본 근로소득 월급, 세금과 공제 설정을 검토하고 입력합니다.
3. 선생님이 별도 문서에 이번 달 근로소득과 사업소득 수업 시수만 입력하면 같은 batch에서 관리자 알림을 생성합니다. 관리자는 알림에서 해당 선생님·급여월의 입력 창을 바로 엽니다.
4. 사업소득은 기본 시급 또는 각 시급 항목의 금액 × 수업 시수를 합산하고 소득세 3%와 지방소득세 0.3%를 공제합니다.
5. 한 선생님에게 두 소득을 모두 입력할 수 있으며, 사회보험은 가입 선생님의 근로소득 부분에만 적용합니다.
6. 수업 여부와 관계없이 근로소득 월급을 포함해 세금과 사회보험 예상액을 계산합니다.
7. 자동 공제와 회계사가 확인한 수동 공제를 함께 검토합니다.
8. 급여 확정 시 선생님별 명세서, 월 마감, 감사 로그를 Firestore batch로 한 번에 저장합니다.
9. 급여 확정 직후 Worker가 현재 발행 차수와 선생님 이메일을 Firestore에서 다시 확인하고, 발송을 실행한 관리자 UID에 연결된 Gmail 계정으로 포털 로그인 안내를 자동 발송합니다. 다른 관리자의 Gmail 연결은 이 계정을 덮어쓰지 않으며, 실패 건은 중복 방지 키를 확인한 뒤 재시도합니다.
10. 확정 문서는 수정·삭제하지 않습니다. 선생님은 자신의 UID가 적힌 `published` 문서만 조회합니다.
11. 선생님의 최초 열람 시 원본과 분리된 `payslipReceipts` 문서를 생성합니다. 재열람은 최초 시간을 덮어쓰지 않습니다.
12. Gmail 발송 성공 시 원본과 분리된 `payslipDeliveries` 문서에 수신자·시각·메시지 ID와 발송 방식을 기록합니다. Gmail 갱신 토큰은 Cloudflare KV에 암호화해 저장하고 PDF는 자동 안내 메일에 포함하지 않습니다.
13. 관리자는 월 급여내역서를 CSV 또는 PDF로 내려받아 회계사와 합의한 안전한 채널로 직접 전달합니다. 회계사는 앱이나 Firebase에 로그인하지 않습니다.

## 보험과 소득 구분 처리

선생님 문서의 `insuranceSettings`는 국민연금·건강보험·고용보험별 가입, 신고 기준액과 기간을 저장합니다. 전체 보험 가입 여부는 이 값에서 계산합니다. 선생님은 가입 여부를 입력하고, 관리자 전용 신고 기준액과 기간은 자기정보 저장 시에도 그대로 보존됩니다. `defaultEmployeePay`는 수업 여부와 무관한 근로소득 월급입니다. 사업소득 시급은 개수와 관계없이 `businessRates` 배열 하나에 ID·금액으로 저장합니다. `teacherMonthlyInputs`에는 시수만 저장하며 급여 계산 때 선생님 문서의 유효 시급과 결합합니다. 이전 필드나 컬렉션을 읽는 변환 계층은 두지 않습니다.

선생님 자기정보 수정은 기본 인적사항, 보험별 가입 체크, 한 개 또는 검증된 여러 시급만 허용합니다. 여러 시급의 표시명은 `시급 1`, `시급 2`로 자동 생성하며 과목명은 입력받지 않습니다. 이메일, UID, 계정 상태, 근로소득 월급, 보험 신고 기준액·기간, 지급일·세금·공제 필드는 Firestore Security Rules에서 관리자 전용입니다. 월별 시수 문서는 본인 UID와 teacherId가 일치하고 급여월이 확정 전일 때만 쓸 수 있습니다. `adminNotifications`에는 급여액 없이 제출자·급여월·제출 시각만 저장합니다.

세금과 사회보험 정책도 분리합니다. `taxPolicies`는 국세청 원천징수 기준과 근로소득 간이세액표를, `insurancePolicies`는 관련 공단의 사회보험 기준을 시행일별 버전으로 보관합니다. 월 계산 시 유효한 최신 버전을 선택하고 확정본에는 두 버전과 계산 결과를 함께 스냅샷으로 저장합니다.

시급 설정은 `teachers`에, 월별 수업시간은 `teacherMonthlyInputs`에 저장합니다. 관리자의 월별 조정은 `payrollOverrides`에 저장하며 과거 수업 건별 컬렉션은 사용하지 않습니다. 확정된 명세서는 계산 전체가 스냅샷으로 저장되므로 이후 월급이나 시급을 바꿔도 과거 확정본은 변하지 않습니다.

## Spark와 Blaze 경계

Spark MVP에서는 관리자 브라우저가 계산과 Firestore 저장을 수행합니다. 계산 결과를 믿기 전에 Security Rules와 확정 전 검토가 필수입니다.

Blaze 단계에서는 다음을 Cloud Functions로 옮기는 것이 좋습니다.

- 서버 기준 급여 재계산 및 변조 검증
- PDF 원본의 서버 생성과 장기 보관
- 예약·일괄 이메일 자동 발송
- 실패 재시도와 발송 이력
- 취소·재발행 워크플로
- Secret Manager의 메일 API 키 관리
