# 남은 설정과 운영 절차

이 문서는 계정 승인, 선생님 수정·비활성화, 급여 확정 취소·재발행 기능을 반영한 뒤 실제 운영을 시작하는 순서입니다. 실제 개인정보를 입력하기 전에 1~3단계를 완료합니다.

## 현재 진행 상황 (2026-08-25)

기능 구현과 기본 Firebase 연결은 완료됐습니다. 관리자 로그인, GitHub Pages 접속, Google 로그인, 승인 도메인, App Check 등록, 최신 Firestore 규칙 게시, 관리자 화면의 `Google 계정 승인 요청` 표시까지 확인했습니다.

### 실제 선생님 정보 입력 전: 5개 남음

- [ ] Firestore 복합 색인 생성 상태 확인
- [ ] 사용하지 않는 Firebase Storage의 읽기·쓰기 차단 상태 확인
- [ ] App Check 유효 요청 지표 확인 후 Firestore 적용 강제
- [ ] 테스트 Google 계정으로 가입 요청·관리자 승인·권한 차단 전체 시험
- [ ] 가상 급여의 1차 발행·PDF 다운로드·확정 취소·2차 재발행 시험

위 5개가 끝나기 전에는 실제 선생님의 이름, 이메일, 급여 정보를 입력하지 않습니다.

### 첫 실제 급여 발행까지: 이후 5단계

1. 실제 선생님 등록과 Google 계정 연결
2. 선생님별 보험 3종 가입·신고 기준액, 근로소득 월급과 과목별 사업소득 시급 등록
3. 선생님의 해당 월 근로·사업 수업시간 제출, 관리자의 교통비·주차료·기타 지급과 과세 처리 입력
4. 자동 계산 결과와 공단 고지액을 회계사와 검토
5. 급여 확정, 선생님 공개·다운로드 확인, 회계사용 내역서 다운로드

따라서 현재는 **실제 개인정보 입력 전 검증 5개가 남았고**, 그 검증 후 첫 실제 급여 발행까지 **운영 단계 5개가 더 남아 있습니다**.

## 1. Firebase 보안 배포 확인

1. [완료] Firebase Console의 Firestore `규칙` 탭에 저장소의 `firestore.rules` 최신 내용을 게시했습니다. 관리자 화면에서 `Google 계정 승인 요청` 영역이 표시되는 것까지 확인했습니다. (2026-08-25)
2. [남음] `firestore.indexes.json`의 복합 색인이 생성됐는지 확인합니다.
3. [남음] Storage 규칙은 사용 전까지 모든 읽기·쓰기를 거부한 상태인지 확인합니다.
4. [완료] Firebase Authentication의 승인된 도메인에 `devrobertson.github.io`가 등록됐고 GitHub Pages에서 Google 로그인이 동작합니다.
5. [부분 완료] App Check reCAPTCHA v3 등록과 사이트 키 적용은 완료했습니다. 요청 지표에서 GitHub Pages 요청이 유효한 요청으로 잡히는지 확인한 뒤 Firestore 적용 강제를 켭니다.

## 2. 가상 계정 보안 시험

실제 선생님 대신 테스트용 Google 계정 한 개로 아래 순서를 수행합니다.

1. 관리자 화면에서 테스트 선생님을 테스트 계정의 Google 이메일로 등록합니다.
2. 로그아웃한 뒤 테스트 계정으로 처음 로그인합니다.
3. `계정 승인 요청을 보냈습니다` 안내가 표시되는지 확인합니다.
4. 관리자로 다시 로그인하고 `선생님 관리 > Google 계정 승인 요청`에서 계정을 연결합니다.
5. 테스트 계정으로 다시 로그인해 선생님 화면만 표시되는지 확인합니다.
6. `등록 정보`에서 이름·연락처·생년월일·성별번호·담당 과목을 수정하고, 이메일과 급여 정보는 수정할 수 없는지 확인합니다.
7. `수업시간 입력`에서 해당 월 시수를 저장하고 관리자 화면의 계산에 반영되는지 확인합니다.
8. 다른 선생님의 정보, 관리자 화면, 미확정 명세서에 접근할 수 없는지 확인합니다.
9. 관리자가 테스트 선생님을 비활성화한 뒤 재로그인이 차단되는지 확인합니다.

## 3. 가상 급여 전체 시험

1. 가상 선생님의 4대보험 가입 여부, 근로소득 월급과 과목별 사업소득 시급을 입력하고 한 명은 두 소득을 모두 설정합니다.
2. 테스트 선생님 계정에서 사업소득 수업 시수를 제출하고, 관리자 월 급여 입력에 반영되는지 확인합니다. 수업이 없는 가입자도 근로소득 계산 대상에 표시되어야 합니다.
3. 자동 세금과 사회보험 공제를 검토하고 필요한 수동 공제를 입력합니다.
4. 1차 급여를 확정하고 테스트 선생님 계정에서 명세서 조회와 PDF 다운로드를 확인합니다.
5. 관리자가 확정 취소 사유를 입력하고 명세서가 선생님 화면에서 사라지는지 확인합니다.
6. 월 지급액 또는 공제액을 수정해 2차로 재발행합니다.
7. 1차 취소 이력은 관리자 화면에 남고 선생님에게는 2차 현재본만 보이는지 확인합니다.

## 4. 실제 선생님 등록

관리자는 선생님마다 이름, Google 이메일, 보험별 가입·신고 기준액·기간, 기본 근로소득 월급, 과목별 사업소득 시급과 지급일을 등록합니다. 연락처, 생년월일 6자리, 성별번호 1자리와 담당 과목은 관리자가 입력하거나 계정 연결 후 선생님이 직접 입력할 수 있습니다. 근로소득이 있는 선생님은 공제대상가족 수, 8~20세 자녀 수와 원천징수 비율도 관리자가 확인합니다. 전체 주민등록번호의 나머지 6자리는 입력하지 않습니다. 연결 전에는 Google 이메일을 수정할 수 있지만 연결 후에는 이메일이 잠깁니다.

선생님에게 포털 링크를 보내 처음 로그인을 요청합니다. 관리자는 승인 요청 이메일과 등록 이메일이 정확히 일치할 때만 연결합니다. 선생님의 UID를 직접 복사하거나 Firebase 문서를 수동으로 만드는 절차는 더 이상 필요하지 않습니다.

## 5. 보험 가입 여부와 소득별 지급 조건 등록

선생님별로 국민연금, 건강보험·장기요양, 고용보험 가입 여부와 각 신고 기준액·적용 기간을 따로 등록합니다. 기본 근로소득 월급과 과목별 사업소득 시급은 양자택일이 아니며 같은 선생님에게 함께 설정할 수 있습니다. 소득 구분은 계약서 명칭만으로 결정하지 말고 회계사·노무사와 실제 고용관계를 확인합니다.

## 6. 월 급여 입력

선생님은 급여월을 선택해 이번 달 근로 수업시간과 사업소득 과목별 수업 시수를 제출합니다. 관리자는 제출값을 검토하고 근로소득 월급, 교통 횟수·교통비·주차료·기타 지급과 보험별 신고 기준액을 입력합니다. 교통비·주차료·기타 지급의 과세 방식은 세무사에게 확인해 선택하며 `처리 미확인` 지급이 남아 있으면 확정이 차단됩니다. 사업소득은 관리자 시급 × 선생님 제출 시수로 총액을 계산하고 3.3%를 원천징수합니다. 수업이 없는 보험 가입 선생님도 근로소득 기본 월급으로 계산됩니다.

## 7. 계산과 회계사 검토

자동 계산은 예상값입니다. 공단 고지액, 기준소득월액·보수월액, 입·퇴사월, 두루누리 지원, 휴직, 정산 내역은 관리자가 확인한 수동 공제액으로 맞춥니다. 월별 급여내역서 CSV 또는 인쇄본을 회계사에게 전달해 소득 구분, 보험, 세액, 비과세, 반올림을 최종 확인합니다.

## 8. 확정과 재발행

검토가 끝나면 급여를 확정합니다. 현재본은 선생님에게 즉시 공개되고 같은 월의 지급액과 공제는 잠깁니다. 오류가 발견되면 `확정 취소`에서 개인정보 없이 사유를 기록하고 수정합니다. 다시 확정하면 2차, 3차처럼 차수가 올라갑니다. 과거 버전과 취소 기록은 삭제하거나 덮어쓰지 않습니다.

## 9. 선생님과 회계사에게 전달

선생님에게는 포털 로그인 안내문을 보내거나 관리자 화면에서 확정 PDF를 내려받아 직접 첨부합니다. Gmail 자동 첨부 발송을 사용하려면 Gmail API, OAuth 동의 화면, `gmail.send` 범위와 관리자 테스트 사용자를 설정합니다. 회계사에게는 월별 급여내역서를 내려받아 합의한 안전한 채널로 직접 보냅니다.

## 10. 매월 반복 체크리스트

- 선생님별 보험 3종 가입·신고 기준액, 근로소득 월급과 과목별 사업소득 시급 확인
- 이번 달 사업소득 수업 시수와 혼합 지급 구성 확인
- 교통비·주차료·기타 지급의 과세 처리 미확인 건이 0건인지 확인
- 공단 고지액과 수동 공제 근거 확인
- 적용 세금·사회보험 정책 버전 확인
- 회계사 검토 후 확정
- 선생님 본인 명세서 열람과 PDF 다운로드 표본 확인
- 발송 대상 이메일과 급여월 재확인
- 회계사 전달 파일의 안전한 보관 또는 삭제

## 11. 이후 추가 개발 후보

- 주휴수당, 연장·야간수당의 전용 계산식과 근태 연동
- 회계사 보안 명부와 식별번호를 결합하는 별도 암호화 서버 연동
- 두 번째 관리자와 관리자 복구 절차
- 개인정보 보관 기간과 전체 관리자용 백업 내보내기
- Blaze 요금제 전환 시 서버 재계산, 예약 발송, 실패 재시도

## 12. AI 도움말 추가 설정 (선택)

관리자 메뉴의 `사용 설명서`와 내장 문서 검색 도움말을 사용할 수 있습니다. 2026-08-25에 Gemini Developer API, App Check와 인증된 사용자 모드 설정을 완료했고, AI Monitoring은 사용 중지했습니다. 앱에서는 `gemini-3.5-flash-lite` 답변을 사용하며 장애 또는 할당량 초과 시 내장 설명서 답변으로 전환합니다.

실제 이름, 이메일, 전화번호, 계좌번호, 주민번호와 급여액은 AI에 입력하지 않습니다. 세부 운영 기준은 `docs/ai-assistant-setup.md`를 따릅니다.

## 운영 시작 조건

실제 선생님 정보를 입력하기 전에 Firestore 색인·Storage 차단·App Check 적용 강제 확인, 가상 계정 권한 시험, 1차 발행·취소·2차 재발행 시험을 모두 완료합니다. 실제 급여를 발행하기 전에는 회계사 계산 검토까지 추가로 완료합니다.
